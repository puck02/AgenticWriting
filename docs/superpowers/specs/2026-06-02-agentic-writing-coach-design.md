# AI 辅助考研英语写作教练设计

## 背景

项目面向自学备考考研英语的学生。核心差异化不是单次作文批改，而是 Agentic 写作教练：系统在每次批改后，根据用户对建议的采纳和拒绝行为，更新个人写作画像，并在未来相似场景中给出更贴合用户表达习惯的优化建议。

首版优先服务个人用户，不做老师端、机构端、课程体系或自动训练计划。

## 产品定位

首版采用“个人写作教练优先”的方案。单篇作文批改是入口，长期画像和表达资产沉淀是核心价值。

核心闭环：

1. 用户提交作文，选择题型并填写题目和正文。
2. 系统给出考研式总评诊断，包括预估得分、分项反馈、核心问题和修改优先级。
3. 用户进入逐句优化，逐条采纳或不采纳 AI 建议。
4. 系统根据用户反馈更新个人写作画像。
5. 下一次批改时，系统读取相关画像，生成更贴合用户偏好的建议。

首版主导航包含：

- 新建批改
- 历史作文
- 我的写作画像
- 个人表达库

首版支持的题型入口包含：

- 英语一大作文：图画作文
- 英语二大作文：图表作文
- 小作文：应用文

这些题型共用统一批改框架，题型只影响评分侧重点、诊断标签和表达建议。

## Agentic 记忆模型

系统维护三类可解释、可查看、可删除的用户记忆。

### 表达风格偏好

表达风格偏好来自用户对句子级建议的采纳、不采纳，以及不采纳原因标签。

示例：

- 正式但不过度复杂
- 优先使用熟悉词汇
- 更接受简洁稳妥表达
- 不喜欢意思变化较大的改写

每个偏好项需要保存证据计数，例如采纳次数、拒绝次数、最近一次触发时间和相关题型。

### 常见错误模式

常见错误模式来自多篇作文的诊断结果，用于识别用户反复出现的问题。

示例：

- 逻辑连接较弱
- 中式英语搭配
- 句子过长
- 表达重复
- 论证过泛

错误模式需要记录出现次数、相关作文、最近一次出现时间和题型分布。

### 个人表达库

个人表达库主要来自用户采纳过的句子级改写。用户采纳建议后，该表达自动进入个人表达库，不需要二次确认。用户可以之后删除表达。

表达库条目需要按以下维度组织：

- 题型
- 话题
- 表达意图
- 原句
- 优化表达
- 采纳时间
- 复用次数

示例表达意图包括：描述趋势、提出建议、解释原因、表达观点、总结升华。

### 用户控制

用户可以查看和删除画像项或表达库条目。首版不支持手动新增和复杂编辑。删除后的记忆不再注入后续批改上下文。

## 单篇作文批改流程

### 阶段一：总评诊断

用户提交作文后，系统先展示整体诊断：

- 预估得分
- 分项得分
- 总体评价
- 核心问题
- 修改优先级

分项得分首版建议包含：

- 内容完整度
- 语言准确性
- 表达丰富度
- 篇章连贯性

### 阶段二：逐句优化

总评后，用户进入句子级建议列表。每条建议包含：

- 原句
- 建议表达
- 修改原因
- 与用户画像的关联说明
- 采纳操作
- 不采纳操作

不采纳时，用户选择固定原因标签。首版不要求自由输入。

原因标签：

- 太复杂
- 不像我会写的
- 意思变了
- 不符合考研风格
- 我更喜欢原句
- 用词不熟悉

### 阶段三：本次画像更新

完成批改后，系统展示本次更新摘要：

- 新增或增强的表达偏好
- 新增或累计的错误模式
- 新加入个人表达库的表达

这一步用于让用户明确感受到系统在学习自己的写作习惯。

## 技术架构

首版采用单体 Web 应用，按模块划分职责，不拆微服务。

### 作文模块

负责提交、保存和展示作文。作文记录包含题型、题目、正文、批改结果、用户反馈和创建时间。

### 批改模块

负责调用大模型生成结构化批改结果。输出必须包含总评、分项评分、核心问题、修改优先级和句子级建议。

批改前，模块从画像模块读取与当前用户、题型、话题和表达意图相关的记忆摘要，并注入模型上下文。

### 反馈模块

负责记录用户对每条句子建议的采纳或不采纳行为。不采纳时保存原因标签。

### 画像模块

负责根据批改结果和用户反馈更新三类记忆：

- 表达风格偏好
- 常见错误模式
- 个人表达库

首版使用明确规则更新画像，不做复杂多 Agent 编排。

更新规则：

- 采纳建议：增强相关表达偏好，并把建议表达加入个人表达库。
- 不采纳建议：根据原因标签降低对应类型建议的后续优先级。
- 重复诊断问题：增加错误模式出现次数。
- 删除画像项：后续检索和提示词构建时排除该记忆。

### 检索模块

负责在批改前选择相关记忆。首版可以先用结构化字段过滤和简单相关性排序，不需要向量检索作为必选能力。

检索依据包括：

- 用户 ID
- 题型
- 话题
- 表达意图
- 记忆类型
- 最近更新时间
- 采纳或出现次数

### 账户模块

负责用户身份和数据隔离。作文、反馈、画像和表达库必须按用户隔离。

## 数据流

1. 用户提交作文。
2. 系统读取当前用户相关画像摘要。
3. 批改模块调用大模型，生成结构化批改结果。
4. 系统保存作文和批改结果。
5. 用户逐条采纳或不采纳建议。
6. 反馈模块保存用户行为。
7. 画像模块根据反馈更新用户画像。
8. 系统展示本次画像更新摘要。
9. 下一次批改时，检索模块读取相关画像并影响建议生成。

## 错误处理

- 大模型调用失败时，保留用户提交的作文，并允许用户重试。
- 大模型输出结构不合法时，最多重试一次；仍不合法则提示批改失败，并保留作文供用户再次发起批改。
- 画像更新失败不能影响批改结果展示，应记录失败状态并允许稍后重试。
- 表达库写入失败不能导致采纳操作丢失，必须先保存用户反馈。
- 用户删除画像项后，该项不得再参与后续检索。

## 测试重点

首版测试重点覆盖以下行为：

- 批改结果结构校验。
- 采纳建议后，表达偏好增强，表达进入个人表达库。
- 不采纳建议后，原因标签被记录，并影响对应偏好。
- 重复错误诊断会累计错误模式次数。
- 删除画像项后，该记忆不再被检索。
- 不同用户之间作文、反馈、画像和表达库隔离。
- 大模型调用失败时，作文提交不丢失。
- 画像更新失败时，批改结果仍可展示。

## 非目标

首版不实现以下能力：

- 老师或机构工作台
- 班级管理
- 课程体系
- 自动训练计划
- 多版本改写选择
- 手动新增或复杂编辑画像
- 复杂多 Agent 编排
- 必选向量检索

这些能力可以在核心闭环验证后再评估。
